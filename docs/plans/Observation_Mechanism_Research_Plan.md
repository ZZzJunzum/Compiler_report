# FusionScope：论文中心与机制验证计划

更新：2026-11-20。证据基线：`1fdf84476d4aef856d0210e954aa480ce03e496d`。

**状态：研究设计，尚无新的性能实验。** 本轮修复了五进程面板的冗余多数判据，并从既有原始计时核验其数值影响。下文的机制、自动改写及投稿贡献均须经新实验检验。历史归档、封存预测和其协议保持原身份，供复现旧结果。

## 1. 一个中心

**研究问题：在保留主输出并满足明确统计语义的 XLA CPU 程序中，联合归约何时有用、何时退化；能否定位造成分化的具体编译条件，并据此形成可验证的改写边界？**

工作标题：**When Does Joint Reduction Help? Studying Exact Activation Statistics in XLA**。

研究首先区分统计计算、主计算变化和优化遗漏，使用匹配对照、编译过程追踪与局部干预检验一个具体机制。只有得到可复现的条件之后，才评估自动改写。现阶段不预设自动方法、普适速度提升或 IR 预测增益成立。

这句话只定义了研究对象，尚不构成新贡献。“融合有权衡”“lowering 影响性能”“观测影响优化”本来就是已知事实。必须进一步得到能够在独立程序上检验的命题：**条件 P 触发路径 L，改变执行结构 E；改变 P 或干预 L 后，结构和性能按预先预期变化。**

## 3. 三项候选贡献及验收条件

### C1：可干预检验的编译机制

得到一个最小触发程序、一个只改变关键条件的对照，说明何时从路径 L1 转入 L2，以及怎样改变 producer 共享、归约循环、向量化、任务划分或库调用。留存 pass 前后 HLO、buffer assignment、LLVM IR/汇编和指纹匹配证据。

验收：在未参与解释构建的实例上复现预测；通过针对性干预验证关键关系。不同 HLO hash、较少 temp bytes 和延迟变化并排出现，仍不足以单独证明因果。

### C2：由机制导出的适用与拒绝条件

只有 C1 成立后实施。输入是程序与统计请求；输出是合法候选、选择/拒绝理由和完整成本。可以先做受限 observation builder/图变换，再视根因决定是否实现 compiler pass。不得依赖样例名称或事后 shape 白名单。

至少对照：原始 separate、always-joint、已有 export-trigger、同信息源码规则；若做调度则加入 cap-16；若试跑候选则加入同预算二选一。oracle 仅作乐观上界。

验收：在冻结规则后的独立程序上，证明相对最强适用基线的额外价值。可以预先把减少实质性退化作为主目标，但须同时报告覆盖率、拒绝率、保留的收益和总成本。拒绝一切不算有效方法。阈值须由开发集和目标场景确定，在确认前封存；不得用确认结果回调规则。

### C3：范围清楚的复验与可复用产物

交付最小例、触发/不触发案例、变换实现、正确性测试、独立时间批次和环境说明。换尺寸、多个请求、多个 seed 和 bootstrap draws 不计作新增架构。

验收：核心正反例经过第二软件环境、第二线程执行配置及真实参数/输入片段检验；结论限定在实际测试范围。它支撑 C1/C2，不以“做了很多实验”独立替代研究贡献。

## 4. 第一轮实验：固定两点，直接测归约轴与实现的交互

主要机制对比固定为 `t_E1_chain`（320×160 affine chain），其余五图是机制对照与探索性分析，不合并成一个主终点。原数据中，两个末轴计数 joint/separate=1.2894；同两点 global 的 31.70 μs 节省未超过 49.29 μs 门槛。三个 global counts 的大收益不能证明两个计数的轴效应，因为观测点数也改变了。

固定同一主计算、参数、输入、两个观测点、count 类型，比较四个变体：

| | 全局归约 | 末轴归约 |
|---|---|---|
| 独立 S | count_S | row_S |
| 联合 J | count_J | row_J |

每列内部要求主输出和统计完全同需求。两列的统计输出形状不同，因此列间不宣称语义等价优化；它们是检验轴对 S/J 效应的实验因子。加入同一 untiled `V0` 只用于观测增量和主计算对照。

在每个会话 s、进程 p、输入 seed k 内，先对每个变体的 round 延迟取中位数 m，再估计：

`D_global(s,p,k) = m(count_J) - m(count_S)`

`D_row(s,p,k) = m(row_J) - m(row_S)`

`I(s,p,k) = D_row(s,p,k) - D_global(s,p,k)`

四个变体必须使用同一个 seed 成块配对。进程内对 manifest 中三个计时 seed 的 I 取等权均值，随后在会话内对五个进程取中位数，作为主要轴交互估计。保留每个 seed 的效应供检查，不按观测效果改变输入权重。相应 sham 控制使用同一聚合顺序。

直接测量 I 的重复性/区间。不能因为一个单独对比过门槛、另一个未过，就宣称二者差异已被检验。负 I/正 I 均为允许结果。

第一轮设计见 [axis_probe_manifest.json](axis_probe_manifest.json)。六张图均已在旧测试中观察，现在用于机制发现，**不是新的盲测集**。先跑 E 的反例及 M/G 的 row 获益对照和 C 的无导出对照；此阶段旨在辨别解释，不评分新选择器。

### 顺序任务

1. 验证当前 JAX/jaxlib 环境能够重现原触发例和关键 HLO，记录实际版本与 flags。
2. 为四个变体留存 optimized HLO、buffer assignment、优化前后 LLVM IR/汇编。现有 row 反例归档缺少这一层，旧大仿射例的 LLVM 证据不能替代。
3. 对照归约循环顺序、向量宽度/累加器、reduction tree、producer 重复和线程任务；说明哪些是静态结构，哪些是实际运行测量。
4. 从观察到的差异提出一个局部干预，并在运行前写下结构与性能预期。避免用“禁掉全部 fusion”作为唯一归因证据。
5. 在相同点数下改变一个维度：固定宽度改行数；固定总元素数改长宽比；固定形状改 producer 或 chain/branch。只有需要解释观测到的边界时才增加因子。
6. `shared`（energy/max）两类减速作为后续容差语义扩展。不要混入精确整数 count 的首个机制命题。

历史 CPU 源码中有 variadic reduction 向量化或 tree rewrite 的限制，但这只是调查线索。必须确认目标版本及触发程序实际走到的路径，才能写成根因；后续 LLVM 也可能自动向量化。

### 第一轮继续/停止门槛

继续：至少得到一个跨新会话可重复的现象，并能把它缩减为可检验的具体后端条件。随后再做机制干预和保留实例验证。

停止扩规模：若只得到“缓冲少了但有时慢”，或变化主要来自主计算/测量上下文，先修复解释与计时。若只剩单版本简单模式遗漏，交付最小复现/补丁并重新评估短文或案例报告定位。

## 5. 语义合同：先保证所比较的确实是同一请求

1. **固定激活数组上的局部证明。** 分量独立的整数加法归约可联合；输入域、轴、初始化和 dtype 必须满足规则，计数和部分和不得溢出 int32。直接使用 StableHLO variadic reduce 的同形状/同归约维要求，不能自动推广到任意异形张量。
2. **整图编译与浮点生产者。** 主输出 allclose 不保证计数相等。独立 diagnostic executable 导出的激活也可能受自身编译影响。局部整数证明不能自动证明融合、FMA 或重计算变化后的激活位模式一致。
3. **分开精确与容差。** count 要求整数相等；energy 等浮点归约只承诺预先定义的数值误差。不得把二者统称为任意输入上的精确等价。参见 [StableHLO reduce](https://openxla.org/stablehlo/spec#reduce)。
4. **阈值压力测试。** 覆盖 ±0、阈值本身、`nextafter` 两侧、抵消输入、真实网络近阈值值；极小数/flush-to-zero、NaN/Inf 明确支持范围。测试失败不能通过放宽整数一致性掩盖。
5. **ReLU 移位单独受约束。** 严格 `>` 且非负阈值在相应实数/有限值语义下可论证；`>=0`、负阈值和未规定特殊值行为不得直接复用。第一轮轴实验不需要移动观测点。

若 producer 数值身份无法保证，工具应限制改写范围或拒绝，论文只报告验证覆盖内的正确性；不宣称有限随机测试等同所有输入证明。

## 6. 性能测量与不确定性

### 旧结果如何处理

五个有限差值的非零中位数天然对应至少三个同号值。`paired_repeat.contrast` 在奇数面板只检查 `abs(median_difference) > floor`，保留偶数面板的历史多数筛选。phase3 两进程 discovery 不能直接删该筛选。

同一组四个 alias 产生的六个差值共享端点。经验 p95 是重复性筛选，不能解释成 95% 显著性或独立误差样本。旧标签的归档核验见 `python -B -m paper.check_repeatability`；它不重新运行性能或正确性实验。

增量 bootstrap 保留现有按家族、尺寸 cluster 成组重采样方式，同时明确每家族只有三个尺寸，进程摘要固定。10,000 是数值重采样次数，不是独立证据数量。

### 新实验单位与配对

- 第一轮至少两个独立会话、覆盖两个日期，重启进程并重新编译；这是发现复验，尚不作为正式置信结论。
- 最终确认建议固定五个会话、覆盖至少三个日期，每会话五个新进程。这个数量是可执行起点，不是自动具有某种统计功效的保证。先依据独立 pilot 的波动决定是否需要调整，并在确认前封存。
- 原始数据必须标记 session/date、process、graph、request、implementation、input/weight seed、round、编译版本、CPU/affinity、线程配置、计时程序指纹。
- 在进程内随机交错 S/J，输入顺序成块配对。跨日漂移以会话为外层单位。多个进程共享机器/会话，不能假设全部独立。
- 若声称输入分布上的性能稳健性，多个输入必须实际进入计时。旧实验中另外的 seed 主要是正确性检查，不能算输入性能重复。
- 把 sham A/A 放进与 A/B 相同的 block 上下文；保留独立校准/核验会话。阈值算法和目标统计量在看到确认 A/B 前冻结。旧的单独 A/A blocks 与候选混合 blocks 的上下文不同，这也是不能把 p95 当 null-test 的原因。
- 要估计“跨五进程中位差”的噪声，控制也须构造同级估计量。不要用共享端点的别名差值数充当独立样本量。

### 报告什么

报告每会话原始效应、跨会话分布、相对和绝对成本、gain/loss/unresolved。图的多个请求与 readout 保持成组。新 CI 的目标范围和聚类层级须预先写清；少量会话/家族时保留条件性解释并做留一会话/家族敏感性检查。预先指定一个主终点，其余为探索性分析；若报告多项显著性检验，应另行定义检验与多重比较方案。

不要以 4/5 同号替换原冗余条件后就声称达成 95% 检验。一个拒绝不了零的结果也不等于证明没有效应。

## 7. 最小环境与真实程序复验

| 变化 | 固定什么 | 检验什么 |
|---|---|---|
| 第二个完整 JAX/jaxlib/XLA 软件环境 | 尽量保持 OS、CPU、输入、case、统计合同 | 是否是版本触发条件，或另一版已修复 |
| 第二种明确线程执行配置 | 同版本、相同图和输入 | 归约收益/退化是否依赖并行路径 |
| 约三个真实网络片段 | 固定预训练参数和真实预处理输入；保存来源与哈希 | 近阈值计数正确性、producer 路径、性能方向 |

第二版本须先确认实际可安装且核心程序可运行，再冻结具体版本和构建标识；只写包版本未必能精确标识 XLA build。线程环境变量不是实际执行线程数的证明；记录 affinity 和可观察的执行配置，必要时单独 profiling。

真实片段按机制覆盖挑选，例如带真实参数的 dense/gated、残差或卷积块。初始化架构只算外部代码来源。无目标机制也应作为范围结果保留，不能只选正例。正式新方法测试所用结构不参与 guard 开发，同模板换尺寸另列。

优先复查：一个明确获益例、两个减速机制例、一个无导出控制，以及新规则接受/拒绝各一例。GPU 不是本轮 CPU 机制闭环的必要条件；未来 GPU 数据另建范围，不能从 CPU 推出 GPU 结果。

## 8. 统一部署成本与使用建议

所有方法按 `C_selection + C_build + N * T_chosen` 计费。

- 可复用已存在的 ordinary executable/HLO 时，只收新增提取、分析、候选构建、试跑与执行费用。
- 为选择专门构建普通程序或候选时，全部收费。若所选 executable 已在候选中构建，复用它，不重复收 build。
- 编译/缓存状态分开：应用已有缓存、只复用普通 HLO、全冷启动；训练是否离线摊销也明确。
- 现有 103.6 ms 基线构建和 1.5 ms 提取是旧环境中位数，不是新工具的成本承诺。
- 给定固定基线 b 和方法 p，报告 `S(N) = (C_b-C_p) + N*(T_b-T_p)`。当 `T_b>T_p` 时，盈亏阈值由 `(C_p-C_b)/(T_b-T_p)` 决定；当不节省单次时间时，不用“未来调用更多”承诺回本。
- 报告 N=1、100、1000、10000 及实际使用场景的范围，附每图分布；不能仅报最有利 N。图的平均比和一个实际工作负载的总耗时分开。

使用建议必须来自结果：哪些条件直接 joint 足够；哪些条件需拒绝；已有 HLO 是否值得分析；短生命图是否值得额外构建。未通过这些比较时，不能以选择器的存在推断部署价值。

| P0，本分支 | 判据修复、统计措辞、可运行归档核验、此计划和首轮 manifest | 已有数值保持可复现；明确哪些结果仍未产生 |

| P2，因果复查 | 单因素与局部干预；预期/实测对照 | 机制能解释触发和不触发例；不是仅有相关性 |
| P3，条件改写 | 有界实现、语义规则、强基线、冻结 guard | 有超过现成 fixed rule 的预先定义价值 |
| P4，独立确认 | 新程序、新会话、第二环境、真实参数输入、完整成本 | 结论在声明范围内成立，退化与拒绝完整报告 |
| P5，重写正文 | 围绕 C1→C2→C3 的叙事与复现说明 | 所有摘要数字对应已完成而非计划中的证据 |

P1 优先集中一至两个人处理，不建议全员扩大配置网格。其余同学可并行准备语义压力输入、版本环境与真实片段。时间预算根据第一次编译/采样耗时估计，不能预先保证几天获得正结果。

三条 no-go：

1. **已有联合归约解释了全部可重复收益。** 新规则既不增加性能也不降低预定退化风险，则停止新优化方法主张。
2. **始终没有可干预机制。** 若剩下的只是 buffer 更少/偶尔更快，或只是一处单版本小遗漏，则以复现案例/补丁评估成果，不升级为通用系统。
3. **独立验证或语义合同失败。** 需要不断看测试集加例外、费用无法回收，或整数统计改变，则不得主张可部署的受约束优化。

这些条件允许得出有价值的否定结论。是否足以投稿取决于最后的新知识与技术深度，不由配置数量、最高加速或会议等级决定。

## 10. 正文重组

1. 问题与实际统计需求：固定输出及精确/容差合同。
2. 承认已有多聚合与插桩优化，指出尚待解释的具体 XLA 问题。
3. 最小正反例及机制干预。
4. 若成立，给出条件改写及正确性范围。
5. 保留图、强基线、独立批次、环境与总成本。
6. 限制与使用建议。

旧成本预测模型移到负结果/附录，保留“当前 IR 增益未证实”；分块保留为主计算混杂的控制；ReLU 表达差异作为相关边界；GPU 只保留明确未来范围。不把这些问题重新排成四个并列主线。

**投稿前应能回答的一句话：读者得到哪个此前未知、可以独立检查并用于判断或修复程序的编译条件？** 若这一句仍答不出来，继续做机制实验，暂不扩大论文主张。
