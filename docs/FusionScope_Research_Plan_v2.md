# FusionScope 研究与实施计划
## 用编译器 IR 预测 XLA 中间激活观测的增量开销

**推荐英文题目**　Predicting the Cost of Observing Intermediate Activations in XLA Using Compiler IR  
**可加的副标题**　A Study of Operator Fusion and Probe Placement  
**研究对象**　给定模型、设备和必须返回的观测信息，研究观测分支的接入位置如何改变生成代码与运行成本，并检验原程序的 IR 能否帮助选择位置。CPU 是可独立完成的轨道；具备 NVIDIA GPU 时，用同一协议验证 GPU kernel 层的机制。正文中，probe 指加入计算图、用来返回指定统计量的分支。

### 1. 研究决策与贡献边界

原题中的 *IR-aware cost modeling* 是方法，激活观测给它一个明确的使用场景。IR 是编译器描述程序的语言；被观测的是运行时激活；模型要预测的是相对于原程序多花多少运行时间。“某个中间态的 cost”只有明确了程序对、设备与计时端点才可以测量。

用户场景是做激活稀疏性分析：推理时要得到指定几层中正激活的数量，同时要保留原有模型输出。开发者能控制监控写在哪一行，但希望少编译、少做性能试跑。对已知的未观测程序，工具生成合法候选，从基线的 IR 提取特征，预测每个候选的代价，推荐一个；独立计时验证这条建议值不值得采用。单批次激活计数描述该批输入下的活跃比例。

| 问题 | 主要实验 | 可被推翻的命题 |
|---|---|---|
| RQ1　为什么相同观测需求会产生不同开销？ | 两种合法位置输出同一个整数，逐例追踪基线与候选的 IR 和运行时间 | 即使信息和输出字节相同，位置仍可能改变融合分组、计算共享或归约的实现；也可能在优化后完全汇合。 |
| RQ2　同时观察两层的成本能否从各层单测结果相加得到？ | 每个两层工作负载做完整九种配置，计算四个双点交互项 | 有些组合会共享一部分代价或互相干扰。真实交互也可能小于噪声。 |
| RQ3　预测能帮助选位置吗？ | 在整类未见图和外部模型块上，对比固定策略、源码特征和基线 IR 特征，再与实测最优比 | IR 可能比“始终在 ReLU 后观察”和廉价源码特征更有用；简单固定规则也可能已经足够。 |

按成果写作时区分三个层次：①已有结论，例如观测可以影响融合；②本组设计，例如同一信息的配对基准和双点实验；③只有实测才有资格写的发现，例如哪些图上 IR 能降低选择损失。课程贡献可以是方法、可复现数据和可验证的有条件结论。主实验不依赖发现数值异常，基础数值校验用于保证比较有效。

### 2. 核心实验：让两个方案给出同一份答案

激活前为 `z`，激活后为 `a = maximum(z, 0)`，模型继续从 `a` 计算 `y`。规定需返回该层的正元素数 `q`。两种实现分别从 `z` 或 `a` 读取数据：

```python
# pre 与 post 的主计算完全相同，mode 在构造顶层 JIT 函数时固定
a = jnp.maximum(z, jnp.float32(0))
y = downstream(a)
source = z if mode == "pre" else a
q = jnp.sum(source > 0, dtype=jnp.int32)
return y, q
```

对于给定的有限实数 z，`z > 0` 当且仅当 `max(z, 0) > 0`。两处严格计数相同，输出均为一个 int32，均包含逐元素比较与整数归约。差别主要在于哪条计算边新增了一个使用者。对两个指定位置，公开接口固定为 `(y, q1, q2)`，保持层顺序、形状和 dtype。不要把不同层的正数总数、全量张量、抽样值彼此替代。

**最小语义例子。** 若 z = [−2, −0, 0, 3, 5]，a = [0, 0, 0, 3, 5]，两端计数均为 2。一次 NumPy 2.3.5 检验使用 seed 42、8×16 FP32 正态输入，覆盖写入 [−1, −0, 0, 1] 四个元素，第二层为 z2 = 0.5·ReLU(z1) − 0.25。四种双点位置均返回 (63, 32)，逐通道计数也一致。这仅验证同一给定张量上的等价关系，尚无 XLA 性能结果。

**编译后仍需验证。** 所有候选使用相同输入和权重，每个归约范围小于 2³¹。对小整数或二进制可精确表示的输入设语义单元测试，包括两种零和正负值。正式 FP32 输入使用多个事先列明的固定 seed，至少三组输入核对 y（按 dtype、图族预登记容差）和 q（整数完全相同）。拿普通、独立参考模型核对小样本。相同公式经不同后端优化，接近零的中间值仍可能受舍入影响。出现 q 不等时，保留输入、种子与失败记录，检查实现；在有关输入上的决策评估中剔除不等价候选，报告分母、覆盖率与失败率。不能为追求计时结论更换“难看”的 seed，也不能在部署时用测试 oracle 排错。若不能保证等价域，限定推荐适用范围，另外报告未经筛选的有效率。

**应用边界。** 这条移动规则只用于有等价证明的查询。比如要看 ReLU 前最小负值，ReLU 后已无法恢复，工具应直接拒绝这个迁移。ReLU 活跃度与计算稀疏性有关，这里只测采集该统计本身有多贵，不推断任务精度或模型质量。

### 3. 工作负载与可解释的实验体量

**阶梯 A · 旧计划作先导。** 复用 Lab 01 的 Jaxpr、StableHLO、优化后 HLO 导出。先用一个逐元素小图做 `only_y / sample / mean / full` 四版。练习区分“新加归约”“原有边界拆开”“多一个输出”；这些版本的信息不同，只用来说明为什么要改进实验设计。再跑主实验的一个九配置小图，有这张实表后才启动批量任务。

**阶梯 B · 主矩阵。** 预登记四个包含两个 ReLU 的图族。相同族内复用源模板与目标位置命名。参数和输入从函数参数传入，层标签固定。

| 图族 | 两处可观测激活如何构造 | 四档规模建议 | 要检验的机制 |
|---|---|---|---|
| E 逐元素链 | 两段逐元素仿射 → ReLU，第二段之后有非平凡读出 | 元素数 4K、32K、256K、1M | 重算廉价、可能完全融合，用作最易解释或最易被优化成相同代码的情形 |
| M 两层 MLP | Dense → ReLU → Dense → ReLU → 固定读出，隐藏宽度 256 | batch 4、16、64、256 | dot、偏置、ReLU 与库调用/融合尾段的边界 |
| N 按行归一化块 | 两段“按行求平方均值 → 缩放偏移 → ReLU”，保留行维和通道维 | [16,256]、[64,256]、[256,256]、[1024,256] | 主图原有归约与新监控归约是否共享数据或分开执行 |
| C 残差卷积块 | Conv3×3 → 偏移 → ReLU → Conv3×3 → 残差加 → ReLU → 读出；推理模式，通道 16、空间 32×32 | batch 1、4、8、16 | 卷积库后端、不透明节点、主图已存在的跨块输出 |

每个图族两种**原始图结构**：链式使用与已有分支使用。分支版让第一个 ReLU 的输出额外参与末端读出（例如与相同形状的末端输出逐元素相加）；对每个固定图结构，九版的主程序相同。选用两处形状匹配的图或预先定义统一形状的读出。分支公式固定，避免零乘、恒等分支或未使用的返回。分支被优化器消除也算观察结果。四个尺寸与两个结构是控制变量，不宣称几十个条件来自几十个独立模型。

一个“条件” = 图族 × 规模 × 图结构；记第一处与第二处激活为 u、v。每条件编译以下九版：

| 观测要求 | 版本 | 用途 |
|---|---|---|
| 无 | ∅ | 基线，T₀ |
| 只观测一层 | u_pre、u_post、v_pre、v_post | 估计各位置的边际成本、检查单点最佳策略 |
| 两层均观测 | pre/pre、pre/post、post/pre、post/post | 对相同的 (y,q1,q2) 做四选一；测两点交互 |

每设备 **4 × 4 × 2 = 32 个条件，32 × 9 = 288 个编译配置**，其中 128 个双点配置、128 个单点配置、32 个基线。每个条件只贡献一次四选一决策。CPU 与 GPU 都完成整套时为 576 个配置，但两个设备分别作图、建模与报告。计时循环次数、输入 seed 和统计重复不计作独立模型数。

**阶梯 C · 真实结构外测。** 优先选择官方 Flax ImageNet ResNet 的一个真实推理 block 和相邻 block 组成的子图，固定上游 commit、模块路径、两处 ReLU 名称、运行形状及权重来源。可加一次完整 ResNet 前向：只为两个事先指定的 ReLU 加观察，跑九配置；列出该开销占整网时延的比例。ResNet 与 C 族相关，应称为外部实现/更大上下文验证。随机权重可验证结构与性能，需写清；如果报告真实数据上的活跃率则改用有来源的权重和输入。保留独立的完整模型/较大子图结果，不用其计时调模型或改特征。

### 4. 机制取证：对哪一条边，发生了什么？

1. 保存每案 StableHLO、优化后 HLO、设备/版本、输入形状、观测契约、编译命令与哈希。优先复用 `jax.jit(f).lower(*args).compile().as_text()`，必要时用独立输出目录的 XLA dumps。对函数与候选位置标注命名范围，再结合操作数与形状建立源代码到 IR 的映射；名称消失时核对数据流。
2. 为每处激活保存三条定位：产生 z 的操作 → ReLU；ReLU → 主链消费者；z 或 a → 检查分支的 compare/reduce。沿 ENTRY 的 tuple 根回溯，包括被调用的 fused computation。分列记录主链关系、观测分支的归约组、是否在同一融合组内多输出、是否能证明重算，以及 custom-call 内部或其他无法定位的原因。
3. 对 pre/post 若归一化后的 HLO 相同，保存比较结果。归一化去掉地址、临时名字和调试元数据，保留依赖、常量、类型、布局、调用和后端配置；仅凭同一文本不宣布机器码和运行时间必然相同。区分“确定同组”“确定分开”“同义改写无单独节点”“证据不足”。不透明案例仍计入覆盖率。
4. 结构分析以 HLO 为准；CPU 上显式 fusion 不是物理循环计数。GPU 个案用 XProf/Nsight Systems 对相同工作区间核对实际 kernel launches、设备时间、memcpy 与库调用。可取得的内存计数器另行报告，说明采集口径。不得把输出逻辑字节或编译器静态估计称为实测 DRAM/HBM 字节。性能 trace 与无 profiler 的正式计时分开。
5. 两项**解释对照**按优先级执行。① 同一 executable 轮流标为 A/A，得到程序没有变化时的时差分布。② 在选定弱差异、大差异各一例上，将生产 z 的前半段和其余计算显式编译为两次 executable，顶层连接且输出契约相同。在单体版和分段版分别比 pre/post；额外调用、物化、调度和布局也随边界变化。用该对照检验现象是否依赖执行边界，结论只写证据支持的范围。
6. 抽查每个图族至少一例，另查结构与时间相矛盾的例子。学生可以拿着摘录从 `y`、`q` 找回相应计算块与调用。保存未解释和不支持假设的案例，允许模型在这类图回退。

### 5. 成本与计时口径

- **主标签。** 同设备、同进程、同图，T₀ 表示只算 y 的稳态延迟；T(c) 表示生成 y 和所需计数的稳态延迟。数据常驻对应设备，`jax.block_until_ready(out)` 等待所有输出，计时止于结果就绪，不含日志及主机拷贝。报告绝对增量 ΔT(c)=T(c)−T₀（µs）及倍率 T(c)/T₀。保留测得的负值。若研究面向宿主读出的使用者，另开同口径对照，仅取回相同统计和双方相同的 y 访问契约，并命名 host-visible latency。
- **执行顺序。** 同一主机、CPU 核/线程配置、库版本；有 GPU 时记录 GPU 型号、驱动、CUDA、编译版本和共享负载。输入准备和 JIT 编译独立计时。每进程对九版先编译/预热，按条件分块，块内每轮等次数随机交错执行；建议独立顺序启动 5 个进程，每案预热约 5–10 次、测 20 轮起，保存每次时间与次序。可用中位数稳定度加测；同一配置的补测保留旧结果与原因。避免并发争用同一测量设备。
- **汇总。** 先在进程内取各配置中位数，再做同进程配对差和比，最后跨进程展示全部点、中位数、范围。先导 A/A 按图规模估计噪声；用独立保留计时批复核前两名。若两者差异与本机波动同量级，标为无法稳定排序并报平局率。将编译时间、端到端同步时间、仅设备 kernel 时间、带 profiler 的时间分列。
- **交互。** 对每一对位置 i,j，在线性时间单位内算 Iᵢⱼ=T(uᵢ,vⱼ)−T(uᵢ)−T(vⱼ)+T₀。例：100、106、107、109 µs 分别对应基线、两次单点和一次双点，则 I=−4 µs，双点比相加预测少 4 µs；这是公式示例。进程内先算 I，按独立重复给范围，与 A/A 伪交互对照（一份基线时序随机分四组，按同样公式处理）。I 的符号只表示非加性；缓存、调用设置、同步、内存和融合都可能参与解释。
- **小程序调度噪声。** 如果 GPU kernel 很短而同步计时主要体现主机开销，保留该端到端定义，并在代表案例加设备时间线。若追加吞吐/批处理指标，所有方案用相同提交批次和同步规则，独立作图。

### 6. 可实现、能被检验的成本模型

**给工具的输入**是未观测程序、需要统计的层、合法位置与目标设备。允许先编译原程序一次来取得其优化后 HLO；推荐时无需分别运行测试候选。核算这一次基线编译和 IR 特征提取的时间。训练阶段对所有候选测时；测试阶段先生成并锁定推荐，再揭开预留的测时与候选 HLO。两者有不同的使用成本。候选 HLO 与实际 kernel/内存计数只用于事后机制分析，或者单独报告一个“已编完所有候选”的方法，不能偷偷进入前者。

| 比较对象 | 可用信息 | 为什么要比 |
|---|---|---|
| B0 固定策略 | 全 pre、全 post，以及训练折中表现最佳的一种固定组合 | 检验工具是否优于写死一条规则 |
| B1 输出字节/尺寸 | q 数、辅助输出字节、形状；同一双点查询字节完全相同，平局用预注册顺序 | 展示只按字节选位置的信息限制 |
| B2 源图模型 | 与 IR 模型相同的拟合器；只用形状、图中操作类别、源图扇出、候选位置、层间距离 | 公平衡量 IR 的增量价值 |
| M 两个子模型 | M1 加基线 HLO 的逐点特征；M2 再加两点特征与交互项 | 分别检验融合信息和非加性特征是否有用 |
| 单点实测相加 | 用四个已观测单点时间预测四个双点时间 | 有额外试跑成本的强对照，检验双点交互的实际价值 |
| 实测最优 | 在符合输出要求的四个具体候选中取最快者 | 给出本次候选集的性能空间；仅供评估 |

**特征字典。** 对每个候选位置，从基线抽取可获得的属性：张量大小、rank、生产者与主链消费者是否同组、该值是否已经是某融合体的输出、使用者数、附近是否有归约或库调用。双点再看是否位于同一显式融合区域、两点间跨越的已知分组数、是否有共享生产者。特征不可读时用缺失标志，并定义退回 B2 或固定策略的规则。预先列清各特征的来源文件、提取时刻、类型和未知值。去掉文件名、运行序号、测量时长、图实例 ID、事后人工赢家标签等泄漏信号。

**建模顺序。** 先拟合可读的岭回归，预测相对基线的 `log(T(c)/T₀)`，或在原始单位建单点加和模型；说明使用的目标与单位。预测交互 I 时用线性时间差。将候选位置及其相应结构特征成对编码；两个点的相加项作为起点，少量同 fusion / 跨分组等交互特征作为增量。B2、M1、M2 共享训练集和调参预算。小型浅树只作可选非线性对照，优先看预测错误能否由数据解释。

**划分与指标。** 每设备做四轮留一图族：一次把一个图族的所有尺寸、近似拓扑、位置、输入 seed 与重复测量全部放入测试，其余三个图族训练；训练折内做归一化与超参数选择。另保存一个完整外部实现作封存测试。报告：
- 预测质量：绝对开销 MAE（µs；换算回原单位需要 T₀，声明基线计时成本）与 log 倍率误差，给出每图族结果。接近零的 ΔT 不适合用相对百分比误差作分母。
- 决策质量：已选方案与该组最快等价候选的差距 `regret = T_chosen / min(T_valid) − 1`；报告中位数、尾部、绝对 µs、等价性覆盖与平局数。比较策略在相同可回答请求上的表现，并单报回退/拒答。实测最优可能受噪声偏向，尽量独立复测，近似平局参照 A/A 波动另报。
- 实际价值：先算“固定 post 与 oracle 之间有多少可赚空间”，再算模型追回了多少。绘制各图族 regret，不把 32 个条件当 32 个独立模型。候选都差不多时如实报告。若复杂策略有一次性额外成本 C，平均每次省 d 微秒，需约 C/d 次调用摊平（C、d 同单位且 d>0）；和“把四版全部编译并试跑”的开销同表比较。

**先导出现这些结果时如何继续。**
- 若预注册图中 pre/post 大多编成同一结构，先用已有分支和真实 block 确认。若仍然相同，就把“编译器已经把位置差异消除了”作为结果，报告等价类覆盖率；继续检验单点成本能否预测双点成本。不要人为关闭优化来制造赢家。
- 若全部组合开销不同但固定 post 接近最优，就报告“何时固定策略已经足够”，量化 oracle 空间、模型构建成本。将重心放在增量成本预测与可解释的失败边界。
- 若单点交互超出噪声而固定位置没有选择空间，把双点交互的可解释建模作为主要发现。若 I 与噪声相当且相加模型够准，就得到一个更便宜的估计方法，并说明适用图族。
- 只有观测位置选择几乎无区分度、且仍希望研究“同一信息有多种实现”时，才将**设备内统计 vs 导出完整激活后在宿主计算同一 q**作为明确标注的新实验。两者都计时到同样的主输出状态与宿主计数可读；包括真实传输和宿主扫描，避免为 CPU 人为强制复制。它回答的是统计放在哪里执行，单独报告，保留原实验全体结果。
- GPU 测量按可申请窗口安排：短窗口先重跑 E/M/真实块的固定子集和关键 trace，记为跨后端案例；有稳定资源再完成 288 配置。可以得到一台 CPU 上完整的成本建模结论；形成关于 GPU kernel 的结论需要 GPU 原始测量。论文数字作为背景，不与本机样本混训。

### 8. 交付物、图与复现入口

工程沿用原仓库。建议一条命令贯通下一阶段，支持 `--backend cpu|gpu`、`--stage pilot|matrix|model|external|report`、按 manifest 恢复及追加运行。ID 由图/规模/拓扑/设备/配置构成，所有产物关联同一 ID。真实模块依赖与 commit 固定，依赖安装、计时设备和日志一并记录。

| 产物 | 最少内容 |
|---|---|
| 配对数据集 | manifest、图定义和等价查询、版本、输入 seed、原始逐轮计时、优化前/后 HLO、逐案成功/失败状态、关键 trace 与真实模块引用 |
| IR 分析与选择工具 | 程序输入一个请求，输出允许的四种位置组合、每种预测的倍率、采用哪个、为何回退；使用锁定模型在外测上演示 |
| 研究图表 | ① 主链与观测分支的 HLO 对照；② 等价位置间时延与噪声；③ 各组实测双点成本对单点加和的偏离；④ 未见图上的固定策略/源码规则/IR 规则的选择损失；⑤ 有条件时，跨设备机制对照 |
| 报告与演示 | 问题与等价证明、已有工作、方法、实验与消融、负结果、适用范围。案例一展示编译器消除差异或固定策略成功，案例二展示最大有证据的交互/决策差异；案例按预定规则选，附全表 |

**结果表字段建议。** configs：program_id、family、shape、topology、site_ids、placement、backend、env_id。timings：config_id、process、round、order、elapsed_ns、endpoint。structure：config_id、edge、relation、aux_path、hlo_file、anchor、unknown_reason。decisions：heldout_group、model、features_available_at、chosen、oracle、regret、valid、fallback、noise_tie。推荐值、测得值、公式示例分别标注。每次报告给学生：已运行哪些、真正学到了什么、最可能的其他解释、下一次什么结果会推翻当前解释。

### 9. 最接近的资料与阅读目的

1. **Snider & Liang，Operator Fusion in XLA: Analysis and Evaluation。** 已分析 XLA 融合与性能，适合作为“观察到融合”这一层的先例。[论文](https://arxiv.org/abs/2301.13062)
2. **Kaufman 等，A Learned Performance Model for Tensor Processing Units，MLSys 2021；OpenXLA GPU Fusion passes。** 前者用程序图建模 tiling/fusion 性能，后者说明 GPU PriorityFusion 和多输出融合。看已有模型要选什么，我们要选什么。[论文](https://proceedings.mlsys.org/paper_files/paper/2021/hash/6bcfac823d40046dca25ef6d6d59cc3f-Abstract.html) · [OpenXLA](https://openxla.org/xla/hlo_to_thunks#fusion-passes)
3. **Cano 等，XLA from the Trenches，2026 arXiv 预印本，§3.2.2、§4.3。** 读调试屏障如何扰动 TPU 融合，以及怎样检查原先的核。引用为动机。FP16 舍入修复和缺陷复现不属于本项目交付。[论文](https://arxiv.org/pdf/2611.00624)
4. **Kreutzer 等，Overhead-Guided Instrumentation Refinement，SC24 ProTools workshop。** 已有在预算下选择 HPC 函数级观测点的研究。本项目比较相同张量监控信息的等价位置及它们在 XLA 下的组合代价。[论文页面](https://sc24.supercomputing.org/proceedings/workshops/workshop_pages/ws_prot110.html)
5. **ReLU Strikes Back，ICLR 2024；TensorRT 量化文档。** 前者给出激活稀疏性的应用背景。后者说明激活统计与融合顺序在校准工程中已有联系。“观测位置有影响”本身不能作为首创声明。[论文](https://proceedings.iclr.cc/paper_files/paper/2024/hash/6cf669c222ad13f60d503736fb2bd15b-Abstract-Conference.html) · [TensorRT](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/inference-library/work-quantized-types.html)
6. **实施文档。** [JAX ReLU 定义](https://docs.jax.dev/en/latest/_autosummary/jax.nn.relu.html) · [XLA HLO dumps](https://openxla.org/xla/hlo_dumps) · [JAX 计时](https://docs.jax.dev/en/latest/benchmarking.html) · [JAX profiling](https://docs.jax.dev/en/latest/profiling.html) · [Flax ResNet 实现](https://github.com/google/flax/blob/main/examples/imagenet/models.py)
