# 实验方法与数据字典

## 复现路径

原始任务书与 Lab 01 均按附件保存，Lab 的示例时间和示例 IR 不参与本研究的数据分析。项目沿用 Lab 的导出方法，在同一 JIT 函数上保存 Jaxpr、StableHLO 和优化后 HLO。根目录 `protocol.json` 在首批正式数据之前提交。每案 ID 为设备、图族/规模/拓扑和位置的组合，例如 `cpu/E0_chain/post_post`。E/M/N/C 的 0–3 分别对应各族四档规模，R1/R2 分别为官方单块和相邻双块。

| 阶段 | 工作负载 | 每案独立进程 | 每个进程内的操作 |
|---|---|---:|---|
| probe4 | E0 链式四种不同观测信息 | 3 | 对每版预热 6 次，20 轮计时 |
| pilot | E、M 各一小一大，九种位置 | 3 | 小图先生成九行配置、四项交互与 IR 摘录 |
| matrix | E/M/N/C × 4 尺寸 × 2 拓扑 × 9 配置 | 5 | 九候选交错，随后为同一基线分配四个 A/A 标签 |
| model | 32 个合成基线、2 个外部基线 | 独立特征导出 | 整图族留出，保存权重、输入特征摘要和预测哈希 |
| confirm | 全部 288 个正式配置 | 3 | 在推荐封存后用新进程重新编译、计时 |
| external_singles | 两个外部图的基线和四个单点 | 3 | 单点相加策略的额外试跑预算，独立封存 |
| external | 两个外部图各 9 个配置 | 5 | 共 18 个新配置；保留同构图与较大上下文的外测结果 |
| boundary | 发现批位置差最小和最大的两个条件 | 5 | 单体与在第一个 z 处分段，比较 pre/pre 与 post/pre |
| lowering | E0、R1 的两种 ReLU 写法 | 仅编译、验算 | 事后机制对照，先用隐式放置，再对齐正式计时的设备放置 |

输入通过 NumPy 固定种子生成，权重用独立的固定流 31，在三个输入批之间保持一致。运行使用 FP32，合成 MLP 两层矩阵乘法，卷积输入为 NHWC、核为 HWIO。归一化块的分母为 sqrt(mean(x²) + 10⁻⁴)。每个合成图的读出为 0.75·a₂ + 0.125，分支版再加 0.25·a₁。卷积第二层额外加入原始输入作为残差。图与所有运行时参数可由生成函数重建。[图定义](../fusionscope/graphs.py)

## 语义和失败处理

小图的独立 NumPy 参考覆盖四个图族、两种拓扑和九种配置，使用可精确表示的输入并覆盖两种零。正式数据以同图、同输入种子的未观测编译程序为 y 的参考，核对形状、dtype、有限性和预登记容差；独立诊断可执行程序导出两个 z，再由主机计算严格正数个数，各候选必须精确返回对应的 int32 标量。正式三个输入批是对已测域的检查。外部图还对未加标记的官方模块核对 y。失败会保存原始输入叶节点、种子、期望和实际结果；离线有效性只用于评估分母。模型选择无法读取该有效性或候选输出。[语义参考](../fusionscope/reference.py) · [计时与校验](../fusionscope/bench.py)

## 计时与数据表

所有进程设置相同的逻辑核亲和性和线程环境，禁用持久编译缓存，使用后端默认优化。CPU 结果包含 Python 调度及等候所有设备输出完成的时间。准备、JIT 和主机读取均在正式区间之外。输入种子 42 的稳态计时在每个条件内部等次数随机交错。A/A 与候选在各自的块内交错，A/A 的四个标签复用同一基线 executable。每次保留运行顺序，避免把循环次数当成独立样本。

| 表 | 一行代表什么 |
|---|---|
| `raw/pN/条件/times.csv` | 一次调用，含阶段内进程、轮次、轮内顺序、位置、纳秒、同步端点 |
| `builds.csv`、`checks.json`、`done.json` | 每版 lowering/编译耗时，每种子校验，以及可恢复的完成标志与哈希 |
| `configs.csv`、`process_medians.csv`、`latencies.csv` | 条件索引、进程内中位数、跨进程配对绝对增量/倍率 |
| `structure.csv`、`hlo_fingerprints.csv`、`hlo_classes.csv` | 两处激活各三条边、源文件和行号、规范化及严格计算体摘要 |
| `process_interactions.csv`、`interactions.csv`、`noise.csv` | 同一进程的单点相加预测和双点实测、跨进程范围、A/A 差值及伪交互 |
| `decisions.csv`、`predictions.csv`、`policy_summary.csv` | 锁定选项、离线验证过的候选集、逐候选误差、每图族与外测的决策统计 |
| `costs.csv`、`boundaries.csv` | 一次基线编译/提取/全面试跑预算与摊销，以及分段前后的位置对照 |

决策损失使用各候选跨进程的延迟中位数。训练目标是进程内倍率的中位数取自然对数。A/A 门槛从进程内四个标签的中位数得到，取所有两两差绝对值的 95 分位。伪交互取两个标签之和减另两个，按同样方式聚合。方法间对照使用共同可回答的请求，各候选覆盖率和回退仍逐项保留。表内开销均区分 ns 和 µs；图中的百分数由无量纲倍率计算。[完整结果表目录](../results/cpu/report/tables/)

## 从返回值回溯优化后 HLO

从 ENTRY 输出 tuple 的 y 和辅助输出分别出发，遇到 fusion / call 就进入被调用体，将形参绑定回调用处实际操作数。跟踪 tuple 元素、实际 compare 的输入、reduce-window 与最终 reduce。每处保存 z→ReLU、ReLU→主消费者、观测输入→比较/归约三行。组别对应一次具体的显式融合调用；同一个源码名可以映射到多份 HLO。多重锚点、缺失名称和不透明调用被显式标记。只有实际为不同导出值且属于同一融合调用才标为共享多输出。重复表达式采用保守的纯算子白名单比对操作、常量、布局及其依赖；该项描述 IR 中的重复，机器执行次数需要其他证据。

规范化保留参数编号、依赖、指令顺序、形状布局、调用签名、常量和后端属性。严格复核连临时名也保留，只去除源位置和调试元数据。两种摘要都属于编译器 IR。[HLO 分析器](../fusionscope/hlo.py) · [OpenXLA HLO dump 文档](https://openxla.org/xla/hlo_dumps)

## 选择工具的特征字典

| 层级 | 可读取的输入与特征 | 缺失值 |
|---|---|---|
| B1 | 两个标量、8 字节、各位置的秩与元素数的 log₂；来自未观测 Jaxpr 的抽象形状 | 同一请求四行特征完全相同，平局按预登记顺序打破 |
| B2 | B1 加 dot、卷积及归约的源码算子数，u→v 的最短源码依赖距离，两个位置是否选 post，以及对应源张量扇出（含返回用途） | 依赖不可达记 −1 |
| M1 | B2 加每个候选端的定位标志、是否位于显式融合、是否为融合导出、主路径使用者数、与下一使用者同组、邻近归约或 dot/conv/custom-call、是否为函数输出 | 位置无法唯一定位时置可读标志 0，对外选择回退 B2 |
| M2 | M1 加两点是否同组、最少 HLO 分组跨越数、是否有相同直接生产者、两点均 post 且同组 | 未知跨组数为 −1，另存 pair_known |

M1/M2 的 HLO 输入仅为未观测基线。每折对 3 个训练图族拟合均值、标准差和固定 α=1 的岭回归。R1/R2 共用用全部四个合成图族训练的封存模型。形状和位置根据实名义契约获得；配置 ID、时间、候选 HLO、手工归因及硬件计数器不作为特征。核验程序还从正式计时基线的 HLO 独立抽取特征，逐项校对锁定的特征向量与回退结果。[特征构造](../fusionscope/features.py) · [拟合与封存](../fusionscope/model.py)

## 对自己的基线调用选择工具

模型接口接受纯 JAX 基线函数和一组实际参数。用两个命名作用域标记要观察的合法 ReLU，名字为 `u_relu`、`v_relu`，每个作用域包住单个 ReLU 表达式。下面以一份项目内基线示范同一接口。部署在新的后端或机器时应使用相应设备的模型。

```python
from pathlib import Path
from fusionscope.common import read
from fusionscope.graphs import inputs, program
from fusionscope.model import recommend_program

models = read(Path("results/cpu/model/models.json"))["external"]["ridge"]
decision = recommend_program(program("R2", "base"), inputs("R2", 42), models)
print(decision["predicted_ratios"], decision["chosen"], decision["reason"])
```

## 课堂演示

1. 打开先导九行表，验证 seed 42 在四个双点行中返回同一对整数。打开对应的优化后 HLO，从 ENTRY 的 q₁ 找到 compare，再定位比较的第一个操作数。
2. 在仓库根目录运行 `run.py --stage recommend --case R2`。保存四个预测倍率和所选位置，随后对照报告中的同一请求及独立测量。
3. 对读 R1 的 pre/pre 和 post/post。检查 post/post 的比较是否仍读取 maximum，再看追加交叉对照中只替换 ReLU 写法会出现几种计算体。
4. 在 N3 链式图上用进程级表手算一项 I，与伪交互门槛比较。回看完整 128 项及第二批的方向，说明这个现象在哪些条件下重复出现。
